STAGE: 16b - Deploy fix: legacy transactions for BOT Chain RPC
STATUS: Complete

PROBLEM:
- npm run deploy:registry failed at submission with:
  InvalidParamsRpcError: 'Invalid parameters were provided to the RPC method.'
- Root cause: viem defaults to EIP-1559 (type 0x2) transactions. BOT Chain's
  RPC (https://rpc.bohr.life) rejects typed transactions (it fakes
  eth_maxPriorityFeePerGas by returning eth_gasPrice). eth_gasPrice works
  fine (returns 20 gwei).

FIX:
- Force legacy transactions (type: 'legacy') everywhere the server writes:
  - scripts/deploy-registry.js  -> deployContract({ type: 'legacy' })
  - api/services/registry.js    -> anchorReport + mintSnapshot writeContract
                                   ({ type: 'legacy' })

VERIFIED:
- Registry service imports OK
- Lint: 20 warnings (unchanged), build passes
- Node confirms eth_gasPrice works (0x4a817c800 = 20 gwei)

STAGE: 16c - DEPLOYED InvestigationRegistry (root cause found + live test)
STATUS: Complete

REAL ROOT CAUSE (the earlier "Invalid parameters" error):
- createWalletClient({ account: PRIVATE_KEY }) passes a raw private key
  STRING. viem's parseAccount() treats a string account as the sender
  ADDRESS, so the 64-hex private key was sent as `from`.
- RPC (go-ethereum) rejected it: 'invalid argument 0: hex string has length
  64, want 40 for common.Address'.
- Fix: use privateKeyToAccount(PRIVATE_KEY) from 'viem/accounts'
  (NOT a top-level 'viem' export in viem 2.55).
- Also kept type: 'legacy' on writes (harmless, works).
