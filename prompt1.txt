AI WALLET INVESTIGATOR

BOT Chain AI dApp - Master Development Prompt

You are the lead developer building a production-quality MVP called AI Wallet Investigator.

The application is a BOT Chain-native AI blockchain investigation dApp. Its primary purpose is to let users investigate a BOT Chain wallet, understand its activity, and ask an AI questions about the wallet using real blockchain data.

The user building this project is not an experienced programmer. Code must therefore be organized, readable, documented, and easy to debug.

Do not create an unnecessarily complicated architecture.

Do not create giant files simply to reduce the number of files.

Do not create excessive abstractions or unnecessary dependencies.

Prefer small, focused files with clear responsibilities.

---

1. PRIMARY GOAL

Build a web application where a user can:

1. Connect a wallet.
2. Enter a BOT Chain wallet address manually.
3. Investigate the address.
4. Retrieve real blockchain activity.
5. Analyze wallet behavior.
6. View assets and transactions.
7. Identify important counterparties.
8. Detect potentially unusual activity.
9. Ask an AI questions about the wallet.
10. Inspect the blockchain evidence behind AI answers.
11. Eventually anchor an investigation report on BOT Chain.

The application must feel like a blockchain investigation terminal, not a generic crypto portfolio tracker and not a generic AI chatbot.

---

2. BOT CHAIN IS THE PRIMARY NETWORK

This is a BOT Chain project.

Do not treat BOT Chain as an afterthought.

The primary network for V1 is:

Network:
BOT Chain Testnet

Chain ID:
968

RPC:
https://rpc.bohr.life

The application should be designed around BOT Chain first.

Multi-chain support may be added later, but do not allow multi-chain complexity to interfere with the BOT Chain MVP.

Create a centralized chain configuration file so network details are not scattered throughout the application.

Never hardcode network configuration in multiple components.

4. WALLET CONNECTION

Use Reown AppKit for wallet connection.

The application must support EIP-1193 compatible wallets where possible.

The wallet connection system must:

- Detect connection state.
- Detect the connected address.
- Detect the connected chain.
- Detect whether the user is on BOT Chain Testnet.
- Request/suggest the correct network when appropriate.
- Clearly display network mismatch.
- Provide a way to reconnect.
- Handle wallet rejection gracefully.
- Handle mobile wallet situations gracefully.
- Never leave the interface permanently stuck on "connecting."

Do not assume a wallet connection succeeded just because a button was clicked.

Always use actual connection state.

- Large outbound transaction
- Unusually high failed transaction activity

34. DOCUMENTATION REQUIREMENT

The developer is not an experienced programmer.

Every major file must have a concise header comment explaining:

- What this file does.
- Why it exists.
- What other part of the application uses it.

Every exported function/component/API route must have a concise comment explaining:

- What it does.
- Main inputs.
- Main output.
- Important side effects.

Do NOT comment every obvious line.

Avoid comments such as:

// Set loading to true

Instead write useful comments such as:

// Starts the investigation request and prevents duplicate scans

Keep comments accurate.

Update comments if implementation changes.
